1. Version Control Fundamentals

Distributed vs. Centralized Systems

Distributed Version Control Systems (DVCS) clone the full repository, including its complete history, onto every local machine. This architecture safeguards data integrity against centralized server failures.

2. Environment Setup & Configuration

System Level Variables

Before executing execution pipelines, global identity variables must be injected into the configuration file framework.

Execute the following parameters within your local shell:

git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"

3. The Core Git Workflow

The Three Trees of Git

Git manages data through a pipeline containing three distinct architectural spaces:

  • Working Directory: The local file system where modifications are actively made.
  • Staging Area (Index): A technical preparation environment tracking assets selected for the next commit snapshot.
  • Commit History (Repository): The permanently recorded cryptographic ledger of project snapshots.

4. Command Reference Matrix

The following technical data layout details high-frequency terminal operations:

Command Syntax Target Lifecycle Layer Mechanical Execution Effect
git init Working Directory Initializes an unpopulated local .git metadata infrastructure layout.
git add <file> Staging Area Stages changes from the local file system into the index file tracking stream.
git commit -m "message" Commit History Serializes staged changes as an immutable node inside the commit graph ledger.
git status Diagnostic Tree Runs comparison checks across the working tree and index tracking states.
